# Tabbit 测试与发布方案

## 1. 质量目标

Tabbit 的高风险不在复杂算法，而在三件事：

1. 事件与 Service Worker 休眠导致状态丢失或重复奖励；
2. 标签整理误关用户页面；
3. 权限、数据行为与商店说明不一致。

测试优先覆盖这些风险，再覆盖视觉细节。

## 2. 测试分层

| 层级 | 工具 | 覆盖内容 | 运行时机 |
| --- | --- | --- | --- |
| 纯函数单元测试 | Vitest | 负载、状态、奖励、迁移、候选规则 | 每次提交 |
| 组件测试 | React Testing Library | Side Panel、设置、领养、错误状态 | 每个 PR |
| Chrome API 适配测试 | Vitest mocks | storage、alarms、tabs 事件、消息协议 | 每个 PR |
| E2E | Playwright + 加载扩展 | 安装、侧边栏、整理、恢复、权限 | 合并到 main |
| 人工探索测试 | Chrome stable/beta | 动画、资源、极端标签数量 | 发布候选 |
| 安全/权限审查 | manifest diff + 人工检查 | 权限、远程请求、CSP、依赖 | 发布候选 |

## 3. 单元测试矩阵

### 负载引擎

- 0、1、5、20、50、1000 标签；
- `soft == hard`、越界设置和损坏数据回退；
- 创建突发边界：0、11、12、13；
- 无标签时 stale 比例不除零；
- 音频数量超过 3 时正确截断；
- score 始终是 0–100 整数；
- 庆祝状态优先级；
- 时间边界恰好结束时重新映射状态。

### 状态防抖

- 阈值附近来回波动不频繁切换；
- 单次跨越 15 分立即升级；
- 降级等待 30 秒；
- UI 关闭期间事件仍写入最终状态；
- 多个并发刷新只保留最新 `capturedAt` 的结果。

### 奖励引擎

- 同一 `eventId` 重放只奖励一次；
- 每类每日上限；
- 本地午夜切日；
- 系统时钟回拨不重复奖励；
- 关闭整个窗口不触发清理奖；
- 恢复刚关闭的标签不扣奖、也不再发奖；
- 等级跨越时余下 XP 保留；
- 20 级上限行为。

### 存储迁移

- 空存储初始化；
- 缺字段补默认值；
- 类型损坏隔离；
- v1 → v2 数据保持；
- 未知未来版本不被覆盖；
- 迁移中断后可重试；
- 备份按保留期清理。

## 4. E2E 场景

### E2E-01 首次领养

1. 在全新 profile 加载扩展；
2. 点击 action 打开 side panel；
3. 输入名称，选择“重度”预设；
4. 完成并关闭面板；
5. 重启浏览器再次打开。

通过条件：直接进入主界面，名称和阈值正确，未产生网络请求。

### E2E-02 状态实时更新

1. 保持 side panel 打开；
2. 程序化打开多个空白标签；
3. 验证负载和 mood 更新；
4. 逐个关闭；
5. 等待防抖窗口。

通过条件：2 秒内升级，降级符合 30 秒稳定规则，没有 UI 闪烁和异常。

### E2E-03 多窗口关闭

1. 创建包含 10 个标签的新窗口；
2. 关闭整个窗口；
3. 检查奖励 ledger。

通过条件：负载下降但不发“整理 5 个标签”奖励。

### E2E-04 权限拒绝与撤销（P1）

1. 进入整理助手并拒绝 `tabs`；
2. 验证基础功能继续；
3. 后续授权并生成候选；
4. 在 `chrome://extensions` 撤销权限；
5. 返回整理页。

通过条件：无崩溃、不循环请求、临时敏感结果清理。

### E2E-05 整理与恢复（P1）

1. 准备普通、固定、发声、活动、重复标签；
2. 进入整理页；
3. 手动选择部分普通标签；
4. 确认关闭；
5. 点击恢复。

通过条件：受保护标签未默认选中，选中项关闭并按顺序恢复，快照 24 小时过期。

## 6. 性能测试

- 使用合成 `Tab` 对象测试 10/100/1000 条聚合；
- DevTools Performance 录制 side panel 空闲 60 秒；
- 扩展管理页观察 Service Worker 能否正常休眠；
- 比较 side panel 关闭前后 CPU；
- 角色资源解码后内存峰值；
- 连续创建/关闭 100 个标签时，storage 写入次数应被合并；
- 构建后统计 JS、CSS、图片和总 zip 体积。

发布阻断：side panel 关闭后持续定时渲染、后台高频 alarm、单套资产 >1.5 MB、1000 标签导致界面冻结。

## 7. 安全与隐私测试

- 解压发布包，确认无远程脚本 URL；
- 搜索 `eval`、`new Function`、`innerHTML`、`<all_urls>`；
- 对 manifest 与上个版本做权限 diff；
- 在代理/DevTools Network 中验证无业务请求；
- 名称输入测试 HTML、超长 Unicode、RTL 和控制字符；
- 导出文件检查不含 URL、标题、自由文本诊断日志；
- P1 整理临时缓存结束后删除；
- 验证 Incognito 默认不开启；若用户手动开启，数据不跨模式泄漏；
- 检查依赖漏洞、许可证和 lockfile 完整性；
- 隐私政策逐条与代码行为对照。

## 8. 可访问性测试

- 全流程只用键盘完成；
- 焦点顺序与视觉顺序一致；
- 每个宠物状态具有 `aria-label` 和文本说明；
- 屏幕阅读器不逐帧朗读动画；
- 200% 缩放无横向滚动；
- 对比度达到 WCAG AA；
- `prefers-reduced-motion` 时无循环位移动画；

## 9. 缺陷等级

| 等级 | 示例 | 发布策略 |
| --- | --- | --- |
| P0 | 误关未选择标签、数据外传、无法启动 | 立即阻断 |
| P1 | 重复发奖、状态损坏、CPU 持续过高 | 阻断公开发布 |
| P2 | 文案错误、偶发动画错帧、布局小问题 | 有负责人和日期可发布 beta |
| P3 | 装饰细节、低频美术问题 | 进入 backlog |

## 10. 商店发布清单

### 代码与构建

- [ ] 从干净 checkout 安装依赖并生成 lockfile；
- [ ] `typecheck`、`test`、`build` 全部通过；
- [ ] 版本号、变更记录和 Git tag 一致；
- [ ] 生产包不含 source map、测试数据、未使用资产；
- [ ] 核查最终 `manifest.json` 权限；
- [ ] zip 可在全新 Chrome profile 加载。

### 内容

- [ ] 128 px 图标和要求尺寸的商店截图；
- [ ] 一句话价值主张明确；
- [ ] 权限解释具体，不写笼统“提升体验”；
- [ ] 隐私政策公开可访问；
- [ ] 支持邮箱或反馈入口可用；
- [ ] 不宣称未完成的跨浏览器、AI 或云功能。

### 分阶段发布

1. 开发者自用 3 天；
2. 3 位熟人 alpha 5 天；
3. 10–20 位目标用户 beta 7 天；
4. 商店非公开/小比例发布；
5. 观察 72 小时再扩大；
6. 保留上一个可回滚构建包。

## 11. Beta 反馈问卷

只问五个核心问题：

1. 一周后你愿意继续保留吗？为什么？
2. 哪一刻最有趣或最有生命感？
3. 哪一刻最打扰、最幼稚或最令人不安？
4. 它有没有促使你主动整理？请描述一次。
5. 如果只能保留一个功能，你会保留什么？

另允许用户主动导出纯聚合统计，上传前明确预览。
